# Complete Cryptagent file guide

This guide describes every original delivered file. There are 492 project files: 42 documentation/configuration/tool files and 450 benchmark files (150 cases × 3). Python may additionally create four cache files; those are explained below. This guide is newly added.

## How the pieces connect

Phase 1 states the rules. Phase 2 defines the request/specification/report shapes and reference C++ interface. Phase 3 provides examples and expected witnesses. Python coordinates; C++ performs cryptographic integration; libsodium implements the primitive. A real model and full verification pipeline are not connected yet.

## Understanding the benchmark names

`F01` through `F30` identify scenario groups, not distinct cryptographic schemes or independent codebases. Six plaintext sizes (0, 1, 15, 16, 17, 1048576 bytes) are paired with five AAD sizes (0, 1, 16, 255, 65536 bytes). Check-specific witnesses may override those sizes—for example, tamper uses empty plaintext.

| Suffix | Meaning |
|---|---|
| reference | No deliberate mutation; still needs validation |
| fixed_nonce | Uses a constant nonce instead of a new random nonce |
| fixed_key | Generates a predictable zero key |
| ignore_auth | Ignores the authentication result |
| omit_aad | Fails to bind caller associated data |
| log_plaintext | Writes plaintext to stderr |
| log_key | Writes key bytes to stderr |
| oversize_plaintext | Removes the application plaintext limit |
| oversize_aad | Removes the application AAD limit during encryption |
| reject_empty | Rejects valid empty plaintext |
| reject_boundary | Rejects the valid inclusive maximum plaintext size |
| multi | Combines two mutations listed in that case metadata |

### The three files in every case

- `candidate.cpp`: the exact C++ source to compile/assess. It uses the shared phase2 header.
- `case.json`: identity, source hash, input sizes, split, expected requirements, trigger checks, label status and expected repairs. It is answer metadata, not the assessment request.
- `CHECK.md`: human explanation of that particular scenario, defect and witness recipe.

Expected labels are authored expectations pending native confirmation. Reference does not mean universally secure. Do not feed held-out answer metadata to the model.
